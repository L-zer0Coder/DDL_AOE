1. 简介
本课程设计任务使用即时战略游戏搭建的博弈系统，测试学生的C++编程水平。该博弈系统是基于《帝国时代1》（微软1997年发行的即时战略游戏）改编的Qt项目。原游戏从模拟人类文明出现的石器时代开始进行，需要玩家搜集资源以生产各种单位及建筑物。当玩家搜集足够的资源，及建筑特定的建筑物之后，就可以升级至下一个文明时代。本系统3.0版本复刻了原游戏石器时代、工具时代和青铜时代的大部分内容和操作，并开发了通过程序控制游戏过程的接口（以下简称为AI接口）。
任务的目标是让同学们通过AI接口编写一系列代码控制游戏过程，并完成指定的游戏目标。AI程序在博弈系统中运行的成绩，将作为C++课程设计项目评分的基础。

2.2  资源管理和作战系统
游戏内一共有四种资源：食物、木材、石头、黄金（游戏目标）。游戏中的资源是维持帝国运转的基础，需要合理规划采集和使用，初始拥有500食物，200木头，0石头，150黄金。
食物可以通过击杀动物后对尸体进行采集、在渔场捕鱼、农场种地获得，木材通过伐木获得，石头通过开采地图上的石堆获取，金子通过开采远方岛屿上的金矿获取。渔场可以由渔船和村民采集，其他各种资源只有村民可以采集。村民在单次采集资源达到上限（基础为10个资源，采集速度为20s/组，部分采集能力可以通过科技升级）后会返回最近的相关建筑存放，再回到资源处继续采集，直到资源采集完成后成为闲置状态。市镇中心可以存放所有类型资源，谷仓可以存放农场和浆果获得的食物，仓库可以存放木头、石头、金子以及打猎获得的食物。因此建议在树林、石堆、金矿、猎物旁建造仓库，以减少采集资源过程中的行走距离。
游戏兵种有棍棒兵、战斧兵、弓箭手、投石兵、方阵兵，阔剑兵，驷马战车，战车弓箭手，复合弓兵等，需要在兵营、靶场、马厩、学院中生产或训练，士兵类型单位只可以进行攻击敌对目标的操作，不能采集资源，且同样占用人口数。每个单位都有生命值、近战/远程攻击力、近战/远程防御等属性。己方部队外观为蓝色，敌方部队外观为红色。
单位攻击敌方时，按攻击间隔时间攻击，每次攻击计算一次伤害。攻击间隔数值为：所有弓箭手1.4，投石车5，其他兵种1.5，狮子和大象1。攻击分为近战和远程，近战必然命中；远程发射一枚抛射物，抛射物命中则命中。命中后计算伤害，为攻击者的攻击减去攻击对象的防御，对应类型的防御只能减少受到对应类型攻击时受到的伤害。当攻击对象的生命值小于等于0时死亡，攻击行为停止。
敌方有独有兵种投石车，具有面杀伤和对建筑的增强杀伤能力。己方拥有一个独有巫师英雄单位，具有转换敌方单位、敌方建筑和治疗己方单位的能力。
己方有一名独有兵种祭司英雄，可以发动“感化”，在一个随机时段内将敌方单位或建筑转化为己方。之后该技能冷却，过一段时间后才能再次使用。转化敌方单位时为远程，转化敌方建筑时必须贴近。转化为己方的单位继承原有的攻防技术。祭司还可以治疗己方单位，自动对附近生命值不满的单位增加生命，也可以命令他走到远处的单位身边治疗。祭司英雄是本次设计的关键角色，必须依赖他才能获得游戏胜利，如果被杀死则立刻游戏失败。
2.3时代特性
本版本游戏开始时，玩家已处于工具时代。玩家可以直接建造房屋、仓库、谷仓、兵营、市场，并在满足前置条件后建造农田、靶场、马厩、学院和箭塔。
在工具时代，玩家可以通过兵营训练棍棒兵、投石兵并升级战斧；通过靶场训练弓箭手，通过马厩训练侦察骑兵；升级箭塔技术建造箭塔；建造市场以建造农田并升级技术。该阶段主要用于快速发展经济、建立基础防线，并准备应对敌方前期进攻。
建造2个工具时代建筑（市场、马厩、靶场）之后，玩家在市镇中心消耗食物，可以升级到铜器时代。铜器时代解锁更强的建筑、兵种和科技，例如骑兵、四马战车、战车弓兵、阔剑兵、复合弓兵、投石车和方阵兵等，同时可以研发更高级的攻防科技和箭塔升级。铜器时代是玩家防守敌方后续进攻并组织最终反击的阶段。

游戏以伪三维方式显示二维游戏平面，将正方形平面显示为45度角的菱形。地图大小为100x100格（Block）的草地，采用以最左侧角落为原点，右下方向为DR轴正方向，右上方向为UR轴正方向的平面坐标系。单个整块格子的坐标称为块坐标(BlockDR(int),BlockUR(int))。地形分为海洋和陆地，陆地具备0-4的整数高度，斜坡用-1表示。
地图上，市政中心所在大陆的格子初始是已探索的。玩家持有的单位和建筑会拥有一定距离的视野，处于视野范围内的格子内容将变为可见，当前不在视野内的格子被标记为已探索，在地图上渲染为灰色，其中的对象仍然可见、可被选取。右下角小地图上会显示各种单位的位置（己方为蓝色，树为绿色，动物为黄色，石头为灰色、黄金为金色，敌方单位为红色），且敌方单位仅有在视野内才会显示在小地图上。海外范围是未知的，标记为黑色，我方单位或者建筑会依照自己的视野将未知部分标记为已探索。
游戏中的部分对象还拥有细节坐标，以浮点数表示(DR(double),UR(double))。每个格子在细节坐标下的尺寸约35.7*35.7(16*根号5,常量表的BLOCKSIDELENGTH)。

3. 游戏目标与评分准则
玩家编写AI逻辑代码即时获取游戏状态，并发送命令控制游戏内的单位、建筑，不断收集资源、建造建筑、研究科技和发展兵力，对抗敌方的进攻，最终发动进攻进入敌方区域。一局游戏总时长不超过30分钟。
胜利条件：用巫师英雄将敌方武器工程厂转变为己方
失败条件：巫师英雄死亡、市政中心被摧毁、或时间耗尽
分数计算方法：胜利按时间计分，时间越短分数越高；失败时按动态分数评价过程质量。
动态分数按下规则记分：首次采集到食物、木材、石材、黄金资源+5分；单种资源累计每满100个+1分（不足100不计分）；每建设一个房屋或农田+1分，其他建筑+2分；升级一个科技+2分；生产普通单位+1分，骑兵、方阵兵单位+2分；杀死一个敌人+2分；摧毁敌方房屋或农田/一般建筑/箭塔分别+2/+4/+5分。游戏运行时分数动态显示。最终成绩由各班老师制定规则转换为百分制，每个班内设定胜利分数线，确保胜利者得分大于失败者。
本次设计的及格线为存活10分钟并升级到铜器时代。
4. AI接口
本博弈系统采取了多线程并行的方式完成代码游戏控制。主线程为博弈系统本体，负责游戏的绘制、规则演绎、手动操作，以及响应用户线程的命令。次线程为用户编程线程，设计了一个类名为UsrAI的接口类。请在成员函数UsrAI::processData()中连续获取游戏信息，再根据自己拟定的策略调用命令函数，控制游戏过程。
4.1获取游戏信息的接口
函数UsrAI::tagInfo getInfo()提供游戏当前帧的数据。
用户需要定义一个tagInfo类型的变量，获得此函数的返回值，如：
tagInfo info = getInfo();
建议在建议在processData()的第一句话获得当前帧的游戏状态。
接口返回结构体结构说明：
tagInfo是总结构，包含tagBuilding、tagResource、tagFarmer、tagArmy等结构体，各个结构代码如下。其中对于Type、ProductSort等分类参数可通过查询常量表（在本部分最后）来获得对应关系。
struct tagInfo
{
vector<tagBuilding> buildings; // 我方建筑列表
vector<tagFarmer> farmers; // 我方农民列表，包括运输船和渔船
vector<tagArmy> armies; // 我方军队列表，包括战船
vector<tagBuilding> enemy_buildings; // 敌方建筑列表
vector<tagFarmer> enemy_farmers; // 敌方农民列表
vector<tagArmy> enemy_armies; // 敌方军队列表
vector<tagResource> resources; // 资源列表
map<int, int> ins_ret; // 指令返回值，map<id, ret>
TerrainData* theMap;
// 地形高度和类型信息，访问方式为(*theMap)[BlockDR][BlockUR]
int GameFrame; // 当前帧数
int civilizationStage; // 文明阶段
int Wood; // 木材数量
int Meat; // 肉类数量
int Stone; // 石头数量
int Gold; // 黄金数量
int Human_MaxNum; // 最大人口数量
};
struct tagTerrain {
int height; // 如果type是Ocean，height是-1，如果是Land，则为0，1，2，3或-1（表示斜坡）
int type; // 枚举类型：Unknown,Ocean,Land
};
struct tagBuilding : tagObj
{
int Type; // 建筑类型
int Blood; // 当前血量
int MaxBlood; // 最大血量
int Percent; // 完成百分比
int Project; // 当前项目；箭塔中可表示当前攻击目标SN
int ProjectPercent; // 项目完成百分比
int Cnt; // 剩余资源量，仅农田等资源建筑有意义
};
struct tagResource
{
double DR,UR; //细节坐标
int BlockDR,BlockUR; //区块坐标
int Type; // 资源类型
int SN; // 序列号
int ProductSort; // 产品种类
int Cnt; // 剩余资源数量
int Blood; // 当前血量
};
struct tagHuman
{
double DR,UR; //细节坐标
int BlockDR,BlockUR; //区块坐标
double DR0,UR0; // 目的地坐标
int NowState; // 当前状态
int WorkObjectSN; // 工作对象序列号
int Blood; // 当前血量
int SN; // 序列号
int attack; // 攻击力
int rangedDefense; // 远程防御
int meleeDefense; // 近战防御
};
struct tagFarmer: public tagHuman
{
int ResourceSort; // 手持资源种类
int Resource; // 手持资源数量；如果是运输船，则代表单位数量
int FarmerSort; // 村民的类型： 0表示陆地生产单位，1表示渔船，2表示运输船
};
struct tagArmy:public tagHuman
{
int Sort;   //军队种类
int ConvertCooldown; //转换冷却时间（仅限巫师）
};
关于可见性需要特别注意：enemy_armies和enemy_farmers主要记录当前视野内可见的敌方单位；敌军离开视野后通常不会继续出现在列表中。enemy_buildings按已探索信息保留得更多一些，已探索过的敌方建筑可能继续出现在enemy_buildings中。
tagGame::update()会对建筑、农民、军队、资源等列表做内部打乱，因此AI代码不要假设列表中的第n个对象每帧都是同一个对象。
4.2发送命令函数及其参数和返回值：
UsrAI类当前提供4个主要Action成员函数向主线程发出控制命令。
（1）对建筑SN发出命令，Action数值见“建筑动作类型常量表”：
int BuildingAction(int SN, int Action)
（2）命令单位SN走向指定细节坐标DR0, UR0：
int HumanMove(int SN, double DR0, double UR0)
（3）将编号为obSN的对象设定为单位SN的对象：
int HumanAction(int SN, int obSN)
村民会自动走向对象并采集、修理、上交或登船；士兵会自动走向对象并攻击。SN与obSN相同时，会按自毁逻辑处理；村民对己方建筑下达HumanAction可以进行建筑（如箭塔）的修复。
（4）命令陆地村民SN在块坐标BlockDR, BlockUR处建造类型为BuildingNum的新建筑：
int HumanBuild(int SN, int BuildingNum, int BlockDR, int BlockUR)
这4个函数的第一个参数都是SN，为执行命令动作的对象编号。SN来自getInfo()返回结构体中的SN字段。HumanMove使用细节坐标double DR/UR；HumanBuild使用块坐标int BlockDR/BlockUR。
系统还提供了几个调试函数：
void DebugText(std::string debugstr)
void DebugText (int debugInt)
void DebugText (double debugDouble)
用于在侧边栏显示用户信息。
为方便方便调试，系统设计了以下作弊函数用于加快游戏进度
void cheatRes();  //调用此函数后，各类资源+500
void cheatAction();  //调用此函数后，之后下达的所有指令都不消耗时间
void cheatAttack(int wave); //触发敌方攻击波，主要用于调试对抗敌方AI
正式测试时作弊函数关闭失效。

5、AI 控制函数错误码
Action 成员函数会返回一个大于0的ID，作为该命令的唯一标识，供用户在下一帧 检查该命令是否执行成功。在发出命令的下一帧，即再次进入 processData()时，可获 取Info 直接用Info.ins_ret[id]查询，得到该命令的执行结果数值获取详细的错误码信息。 错误码仅适合在调试时检查，实际编写代码时应该避免依赖错误码来处理人物逻辑。
错误码常量表如下：
#define ACTION_INVALID_SN -1 //SN不存在或非法控制SN

7、综合示例：简单盖一座房屋
tagInfo info;
int begin_x = -1, begin_y = -1;
int center_x = -1, center_y = -1;
bool home_flag = false;
// 从市镇中心开始查找2*2的空地，通过引用返回空地左下角坐标x,y
/*
使用及修改建议：
1.拓展此函数以适应不同大小建筑的地址寻找功能
2.继续判断当前位置是否已经存在建筑、资源、人物等占地单位
3.可以考虑使用更优的搜索算法
4.可以考虑将建筑距离资源、敌人等单位的距离纳入考量范围
*/
int find_block(int &x, int &y){
for (int i = begin_x + 1; i < MAP_L; i++){
for (int j = begin_y + 1; j < MAP_U; j++){
//超出地图范围跳过
if (i + 1 >= MAP_L || j + 1 >= MAP_U)
continue;
// 获取四个格子的信息
tagTerrain t00 = (*info.theMap)[i][j];
tagTerrain t10 = (*info.theMap)[i + 1][j];
tagTerrain t01 = (*info.theMap)[i][j + 1];
tagTerrain t11 = (*info.theMap)[i + 1][j + 1];
// 检查四个格子是否都是陆地
if (t00.type != MAPPATTERN_GRASS || t10.type != MAPPATTERN_GRASS ||
t01.type != MAPPATTERN_GRASS || t11.type != MAPPATTERN_GRASS)
continue;
// 检查四个格子高度是否相等（确保是平地）
if (t00.height == t10.height &&
t00.height == t01.height &&
t00.height == t11.height){
x = i;
y = j;
return 1; // 找到合法空地
}
}
}
return 0; // 未找到
}

{

if (center_x == -1){

center_x = building.BlockDR;
center_y = building.BlockUR;

}
}
}
// 初始化搜索的起始坐标
if (begin_x == -1){
begin_x = center_x;

}

homeCount++;
}
}
// 如果房屋数量不足且资源充足，则寻找可以建造房屋的坐标
// 这里我们假设要建造三个房屋
if (homeCount < 3 && info.Wood >= BUILD_HOUSE_WOOD){
int home_x = -1, home_y = -1;
// 如果当前有地址可以修建房屋

if (farmer.NowState == HUMAN_STATE_IDLE){
HumanBuild(farmer.SN, BUILDING_HOME, home_x, home_y);

begin_y = home_y;

6、敌方进攻和防守策略
本版本地图中预置了50个敌方军队单位，包括地图上零散的兵群和敌方基地的三十个兵；敌方基地附近还设有5座箭塔和1座攻城武器厂。敌方不会自行训练或补充部队，从地图预置军队中按波次选择单位出战。敌方的各种技术已经全部升完，军队实力强大。
第一波约在第6000帧（默认速度下约4分钟）发动。兵力为2斧头兵、1弓箭手，攻击优先级为：攻击自己的第一个对象（包括箭塔，士兵，祭司，农民等）＞玩家祭司＞玩家农民。记录到3名曾被本波锁定的村民死亡后，剩余部队撤回各自出发位置。
第二波约在第13500帧（约9分钟）发动，由第一波残余兵力加上2个方阵兵、1个阔剑兵、1个复合弓兵和2个战车弓兵组成，即新增6名士兵。敌方攻击优先级同第一波，战车弓兵优先猎杀巫师英雄。记录到8名曾被本波锁定的村民死亡后，剩余部队撤退；即使祭司仍然存活，该结束条件也会立即生效。
第三波约在第21000帧（约14分钟）发动，由前两波残余兵力加上10个左右新的铜器时代单位组成。可选兵种包括阔剑兵、复合弓兵、战车弓兵、四马战车、骑兵、方阵兵以及肯定存在的2辆投石车。第三波不会撤退，并会强制结束前两波的波次状态。除投石车外，其他单位目标优先级同前两波。投石车攻击优先级为：箭塔＞弓箭手>其他建筑>玩家祭司＞玩家农民>其他单位，第三波单位全部死亡，或者已经找不到任何可攻击目标时，本波结束。
防守方面，玩家军队或村民进入攻城武器厂约15格范围后，守军会主动迎击；守军自身追击至距离核心超过约18格时，会返回原防守位置。远程部队的追击范围会减去自己的射程。
守军中的3个骑兵和2个战车射手还会组成独立的厂区祭司猎手小队，优先攻击距离攻城武器厂20格以内的玩家祭司，直到杀死祭司或被消灭为止。箭塔也会自动攻击其攻击范围内距离最近的玩家单位，直到杀死或该单位离开射程范围。
7.获得游戏胜利的基本步骤
本次游戏的目标是先完成基地发展，防守住敌方连续三波进攻，最后组织反击击败敌军，将敌方武器工程厂转变为己方。玩家开局拥有少量村民、基础资源和基础建筑，需要尽快采集食物、木材、石头等资源，建造房屋、仓库、兵营等基础设施，并持续生产村民扩大经济。游戏过程中敌方会分三波向玩家基地发动进攻，且进攻强度逐渐提高，因此玩家需要在发展经济的同时训练军队、建造箭塔、升级科技，保护基地和资源点。待三波进攻被成功防守后，再集中主力部队反攻敌方基地，最终取得胜利。
第一阶段：控制村民采集食物和木材，持续生产村民，建造房屋、仓库、兵营等基础建筑，建造工具时代建筑（市场、马厩、靶场），保证资源和人口稳定增长，尽快升级到铜器时代。
第二阶段：在敌方第一波进攻前训练基础士兵，必要时建造箭塔，在基地附近形成初步防线，避免经济区被敌军破坏，可用己方巫师英雄转变敌方单位减轻防守压力。
第三阶段：面对敌方第二波、第三波进攻时，继续补充军队并升级关键科技，集中部队和防御建筑消灭来袭敌军，守住市镇中心和主要资源点。
第四阶段：成功防守三波进攻后，集合剩余主力和新训练部队，向敌方基地发起反击，消灭敌方军队和箭塔，摧毁敌军，转化敌方武器工程厂后获得胜利。
8. 编写AI代码的注意事项：
UsrAI::processData()是系统调用 AI 代码的入口。注意这个调用不是一次性的， 而是每帧会尝试调用一次。游戏核心本身是按时间发起的事件处理机制， UsrAI::processData()函数实际上是一个会定时执行的循环体。编程时必须考虑这个因素，至少有两个后果：a.几乎所有的游戏动作都需要有控制条件，不然就成了每帧都发起，会达不到预期；b.控制动作、记录中间过程用的变量，都必须是静态或者全局的，使用局部变量进入代码会被重新初始化造成错误。
发出控制命令成功，不等于命令可以执行成功。例如命令村民建造建筑时，如果 目标位置上有障碍物（包括单位），则不能建造，该村民的状态会回到 HUMAN_STATE_IDLE。若目标对象不可达，村民可能会持续寻路尝试靠近目标，此时会一直保持非IDLE状态，需要自己根据情况写代码处理该状态。示例代码中用了其他方法判定村民有无进行命令动作，也是有效的。
本系统采用了多线程，AI代码和游戏主线程在时间上可以看作是并行的。AI代码的执行过程不影响主线程的进度，可以执行复杂度较高的代码。但是时间过长会延缓发出指令的时间，有可能会造成指令和期待有差异，因为发指令时的游戏局势已经变化了。建议AI代码每轮执行的时间控制在几帧以内。
原游戏的节奏较慢，完成一次任务的时间较长，因此系统提供了倍速功能。在界面右上方有四个可以点击的圆点，分别表示游戏运行在1、2、4、8倍速(8倍速时无法使用鼠标操作)。我们在实际批改运行时，为节省运行时间将使用8倍速运行，同学们在设计和测试AI代码时也要考虑这一因素，最终的测试应当在8倍速下完成。
游戏调试时可以使用Qt的debug模式编译，方便动态调试，但代码性能较低。我们在最终测试时会使用release模式编译，提高测试性能。同学们提交代码前也要自己用release模式编译测试。
我们准备了多幅地图，运行时（包括测试时）随机选用，并赋予一个随机旋转。为调试方便，可以通过命令行参数来选择使用哪一幅，并且固定旋转参数：使用–map 地图名（如map.njust）可以固定地图；–rotate 角度（0/90/180/270）可以使用旋转特定角度后的地图。在配置文件config.json中也可以通过设置GlobalVision的false/true来关闭/打开战争迷雾，便于调试。
UsrAI::processData()中，所有语句都可以重写。但重写在UsrAI.cpp以外的代码无效，最终提交作业只提交UsrAI.cpp和UsrAI.h。建议多设计一些功能函数作为UsrAI的成员函数，分散processData()的压力，增加代码条理；多个成员函数需要共同使用的变量新增为UsrAI的数据成员。新增的UsrAI成员函数和成员变量需要在UsrAI.h中声明。
游戏进行时，主线程会在右侧的文字窗口显示指示文字，包括游戏的进度和对AI命令的响应。AI线程也可以使用此窗口显示信息用于调试，使用方法见前述AI示例代码。调试时也可使用QT的输出窗口，建议将临时输出的内容输出到QT窗口，重要的调试信息输出到游戏的文字窗口。
本任务较为复杂，按要求完成代码量较大。同学们设计代码时应当多使用函数或类（类在提交时，代码必须并入 UsrAI.cpp），使代码更有条理、更简短。 代码中用到常数的地方尽量使用#define 定义，以增强可读性和方便调试。有能力的同学可以设计通用的调度系统调度农民和军事单位，以简化编程，提高代码效率。
